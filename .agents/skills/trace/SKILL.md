# Trace

Explain how the work produced the result and where it came from. Use the conversation and inspect relevant files, changes, and sources as needed. This is a read-only explanation; do not repeat or change the original work.

- Start with the result, then connect the important steps that led to it. Explain why those steps mattered.
- Show where the information came from and how it was used. Distinguish sources you read from files or external resources you changed.
- Link directly to the relevant files, pages, or changes beside the explanation they support. Use absolute local file links, with line numbers when useful, and exact web pages rather than site homepages. For deleted files, link to a recorded change when available.
- Explain what changed in each relevant place and why. Keep changes that already existed separate from the work being explained.
- Say how the result was checked and what remains uncertain. Do not invent missing history or sources; distinguish confirmed facts from inferences.

Use everyday language. Leave out tool names, commands, session IDs, model settings, and other machinery unless the user asks or those details are necessary to explain what happened. Never expose secrets.

Keep small explanations short. Use a compact table or flow only when it makes the connection between steps and sources easier to follow.
